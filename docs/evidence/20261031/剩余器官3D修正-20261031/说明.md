## 3. 方法与注意事项

1. **“修改前”的数字不是在改动之前现场运行的。** 先只读量取了一次，再改动；为了让“修改前”和“修改后”用同一份脚本，之后用备份里的旧 `organ-models.ts` 在临时目录拼出一棵“旧树”（其余目录用链接指向项目），在旧树上运行脚本和新测试。旧树放在临时目录，没有写进项目。
2. **分析脚本有两版输出。** `修改前/analysis-remaining.txt`（第一版）按旧取值的假设计算头部项；`修改前/analysis-remaining-v2.txt`（第二版，同一份脚本加了两处）按注册表的取值和旋转（与 `OrganModel` 同一公式）量取，并增加“当前取值对照”（E 节）和注册表自身的眼球—脑重叠量。第一版输出保留，没有覆盖；文档引用的修改前数字来自第二版。`修改后/analysis-remaining.txt` 是同一份第二版脚本在新取值上的输出。`analysis-stdout.log`、`analysis-v2-stdout.log`、`compare-stdout.log` 分别与同目录的 `analysis-remaining.txt`、`analysis-remaining-v2.txt`、`report.txt` 内容相同（标准输出副本）。
3. **`修改前/report.txt`、`comparison.json`、`head-checks.txt`** 是改动之前的第一次只读对比（肺、脑、眼球与图谱的外形对照，脑的朝向与眼球的朝向，图谱头部与人形轮廓）。产生它们的临时脚本**没有保存**；其中的结论已由保存下来的 `analyze-remaining.mjs` 的输出重新量取，数字可交叉核对。
4. **新测试的破坏检查**：`修改前/new-tests-on-old-registry.log` 把新增的三项测试放到旧注册表上运行，三项全部失败，信息写出了超出的位置；`修改后/new-tests-on-new-registry.log` 是同一份测试在新注册表上三项通过。
5. **类型检查与 ESLint**：`修改后/tsc.log`、`lint.log` 是第一次运行的输出（没有输出；当时没有把退出码写进日志）。之后重跑并把退出码写进 `tsc-退出码.log`、`lint-退出码.log`，两个都是 0。类型检查在构建之后运行，因为 `.next/types` 在检查范围内。
6. **合成完整链路**（`修改后/e2e/`）：生产构建 + 本地合成登录令牌服务与 PostgREST 子集翻译器（在 PGlite 中执行 `supabase/schema.sql`）+ AI 桩；`MEDPLAN_TEST_OUTPUT` 指向这个新文件夹，没有覆盖旧证据。19/19 通过。**不是真实的 Supabase、GoTrue、PostgREST 或 AI 服务。**

## 6. 后续处理：左右肾独立配准（2026-10-31）

本节记录上述历史验证之后的新增工作；第 1—5 节保留当时的原始结论，新的证据另存于 [`../左右肾独立配准-20261031/`](../左右肾独立配准-20261031/)。

- **处理的问题**：原有人体概览的肾脏是一份双肾合并网格，左右等高，不能通过整体移动对齐图谱。分析发现原网格有 399 个三角面跨中线，因此没有直接切割网格。
- **修改**：人体概览和手术模拟“人体层面”使用 HuBMAP HRA 的[男性左肾 v1.3](https://purl.humanatlas.io/ref-organ/kidney-male-left/v1.3)与[男性右肾 v1.3](https://purl.humanatlas.io/ref-organ/kidney-male-right/v1.3)，按 BodyParts3D 图谱的左右肾包围盒分别居中并按最长边缩放。右肾中心比左肾低约 **1.85 厘米**；这些是男性参考模型，女性模式也共用，不能代表个体患者。
- **代码与资产**：`src/lib/organ-models.ts` 加入概览用分部模型配置；`src/components/sim/BodyOverviewScene.tsx` 支持各分部独立定位并保留选择、高亮与调暗；`public/models/hra-kidney-left-male.glb` 和 `hra-kidney-right-male.glb` 为 CC BY 4.0 参考模型；`README.md` 补充来源。学习中心器官特写及手术模拟的器官层面仍使用既有模型，原有位置配置保留给标签和相机。
- **验证**：新增回归测试检查左右模型均能解析、左右位置和尺寸与图谱包围盒一致、右肾较低；图谱相关测试 **10/10**，完整 `npm test` **99/99**，修改文件的 ESLint 通过，`npm run build` 通过。合成端到端流程 **19/19**；首次流程的 19 项检查均已通过，但因指定的结果目录不存在而写文件失败，创建目录后重跑并成功保存。
