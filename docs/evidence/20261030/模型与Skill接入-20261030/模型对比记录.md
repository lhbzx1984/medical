- 9 个文件合计约 28.6 MiB、约 312 万个三角形；全部经 glTF-Transform 4.4.2 处理（Meshopt 压缩，多数含 WebP 纹理）。
- **所有节点和材质名都以 `tripo_` 开头**（如 `tripo_node_…`、`tripo_material_…`）。这是 Tripo 3D 工具导出的常见命名；glTF 的 asset 字段里没有作者、版权或许可信息。据此**推测**这些模型很可能由 AI 3D 生成工具产生，而不是来自解剖参考数据。这是推测，不是已证实的来源。
- 每个器官 30 万以上三角形、单个文件 2 到 6 MiB，手机上的首屏加载、帧率和内存**尚未测量**；作为对照，图谱里的胃只有 1,686 个三角形。
- 判断：目前没有更优且可核验的替代品，所以**不替换**。需要在界面和 README 里把它们标为“教学示意，来源与授权待确认”，并向上游或原作者确认授权。**这些模型的解剖准确性我没有能力证明，也不能由它们的面数来推断。**

## 4. 胃 FJ2564（图谱网格）实测

读取 `body-9.bin.gz` 解码后得到：

| 项目 | 结果 |
| --- | --- |
| 基本完整性 | 852 顶点、1,686 三角形；坐标全部有限；索引最大 851，没越界；无退化三角形；1 个连通块 |
| 包围盒 | 实际 [-0.02877, 1.11799, -0.01852] 到 [0.10552, 1.23500, 0.09437] 米，与 atlas.json 记录一致（最大偏差约 0.18 毫米）；尺寸约 13.4×11.7×11.3 厘米 |
| 闭合性 | 2,518 条边被两个三角形共用，**22 条边只被一个三角形使用**，即有少量开口（可能是贲门和幽门处，未验证）。表面积 0.0383 m²，近似体积约 566 mL（因有开口，仅为近似） |
| 左右约定 | 图谱 +X 是患者左侧：胃 x=+0.038，脾 +0.085，左肾 +0.062，降结肠 +0.050，左心室腔 +0.038；而右肾 −0.059，胆囊 −0.045，升结肠 −0.095，右心房 −0.016。前方是 +Z（胸骨 z=+0.089，胸椎 z≈−0.05）。胃的位置与这个约定一致 |
| **法线问题** | 解码后的法线与三角形绕向**几乎完全相反**：胃上 99.8% 的三角形不一致；用质心做外向判断，绕向给出的外向比例为 91.8%，存储法线只有 14.0%。在同一数据块里随机抽样 12 个其他结构，一致比例只有 0% 到 7.4%。法线长度在 0.73 到 1.40 之间，也不是单位向量 |
| 精度与范围 | atlas.json 记录整体经 meshoptimizer 简化（最大相对误差 0.002），数据范围是男性参考解剖 |

对转换的含义：

1. 生成 GLB 时**不能直接带入存储的法线**，应按三角形绕向重新计算外向法线并单位化，再用渲染截图确认。
2. 图谱查看器现在用这些反向法线着色。是否造成可见的光照反转，需要看截图，我还没有看。
3. 女性视图复用这个男性参考的简化网格时，界面必须注明来源，不能称“更细致”或“女性胃”。
4. 衍生 GLB 沿用 CC BY 4.0：用指定署名文字，并写明改动（格式转换、法线重算、居中缩放）。

## 5. 乳腺候选（HuBMAP v1.3）实测

固定提交 `f1a3a63…` 下：

| 项目 | 左 `VH_F_mammary_gland_L.glb` | 右 `VH_F_mammary_gland_R.glb` |
| --- | --- | --- |
| 路径 | `VH_Female/v1.3/` | 同左 |
| 大小 | 13,727,160 字节（blob `0f43f1cf…`，与交接文档一致） | 24,388,424 字节（blob `720c8cb9…`） |
| 三角形 / 顶点 | 270,799 / 443,117 | 585,330 / 611,165 |
| 结构 | 8 个网格：脂肪、乳晕结节、乳头、乳晕、乳腺小叶、输乳管主干、输乳窦、悬韧带 | 同样 8 个 |
| 外形尺寸 | 12.8×18.2×11.2 厘米（米制） | 12.8×18.0×11.3 厘米 |
| 位置 | x 从 +0.011 到 +0.139（左侧为 +X，与图谱约定一致），仍在 Visible Human 女性的身体坐标里，需要平移到本项目的人体概览坐标 | x 从 −0.150 到 −0.022 |
| 纹理 / 压缩 | 无纹理、无压缩（Babylon.js 的 Maya 导出器） | 同左 |

判断：

- 这是官方仓库里命名清晰的细分结构，来源和哈希可核实，**作为候选合格**。
- **左右不是镜像**：右侧三角形数是左侧的 2.2 倍，因此不能用左侧镜像冒充右侧。若只接入一侧，必须在界面标明是左乳；两侧都接入则总计约 85.6 万三角形、约 38.1 MB（36.4 MiB）原始体积。
- 未做减面和 Meshopt 压缩前，手机上很可能太重；需要先做资产优化（这属于对原模型的修改，须记录），再测量加载时间和内存。
- 仓库自带的 LICENSE 是 CC BY 4.0，但我没有找到针对这个文件的专家审核声明，也没有找到它的雕刻或扫描来源说明；NIH 条目对应的是另一个文件。因此界面上只能称“解剖参考模型”，不能称“真实患者”或“用于个体手术规划”。
- 仓库 `UnderReview/` 目录里只有肺和支气管软骨的待审文件，与乳腺无关。

## 6. 其他发现（需要浏览器目视确认，尚未下结论）

- **概览 3D 场景里肝和心的 X 坐标**：`organ-models.ts` 注释写明人体面朝 +Z，图谱按同一朝向时 +X 是患者左侧。`liver.bodyPosition.x = +0.055` 落在左侧，`heart.bodyPosition.x = −0.015` 偏右，但图谱里心脏的右心房 x=−0.016、左心室 x=+0.038，心脏大致在中线附近偏左。这可能是左右放反，也可能是模型自身的朝向抵消了它，**需要在浏览器里看实际摆放**才能确定。这不是本次新增的问题，也没有修改。
